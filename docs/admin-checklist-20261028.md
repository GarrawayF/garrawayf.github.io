# 管理票のチェックリスト改善（未公開）

## 変更点

- 共有管理者の管理票に、工程別の全作業チェックリストを表示します。
- サーバーの既存記録から「✓ 記録済み」「再確認」「未記録」「先に確認が必要」を表示します。「未記録」は実作業が未実施という断定ではありません。
- 必要な行を選ぶと、その行の直下で既存の記録フォームを使えます。「ほかの作業を選ぶ」の展開と選択欄の操作を省きます。
- 保存には引き続き明示的な記録ボタンを使います。行を選ぶだけでは記録・承認・通知しません。
- 開催可の判断は「判断・通知を確認」と表示し、判断者・開催候補、先行条件と既存の通知操作を維持します。
- 同意書・終了報告の証跡、再確認の理由、日付、共有保存、競合・結果不明時の扱いを維持します。
- 作業を切り替える前に未保存入力を確認します。キャンセルは元の選択と入力を維持し、破棄を選んだ場合だけ切り替えます。

## 変えないもの

申請者フォーム、認証、権限、API、データ形式、承認・通知、カレンダー連携、既存案件、別の Work の依存修正は変更しません。新しいブラウザー内の完了データ保存も追加しません。単なるチェックボックスで承認や通知を実行しません。

## 検証

- ベース：main b7a1975382fd79fd7cbe91a78cbbf63a5d92e29d。
- Node 24.22.1：新しい単体テスト、全 JavaScript 構文、全既存 inline-script の CSP ハッシュを確認。
- 架空データだけを用いた jsdom 26.1.0 の DOM 検証：63 チェック通過。初期表示、行選択、保存なしでの画面移動、未保存のキャンセルと破棄、証跡・再確認理由の必須、承認の入力と前提条件、保存前の状態維持、サーバー再読時の状態表示、無関係な未保存フォームの保護、保存中の行ロックを確認。
- DOM 検証用 jsdom は一時的なテスト環境だけで使用し、アプリの依存には追加しません。
- 変更された inline-script は既存の進捗表示モジュール 1 本のみ。認証と API の書込・再試行モジュールはバイト一致。CSP の許可元は拡張せず、変更したスクリプトのハッシュだけ更新。
- 実案件の操作・申請・承認・メール送信は行っていません。

## 未実施と公開条件

ローカル Chromium は実行環境の socket 制限で起動できず、別の起動も実行環境のエラーとなりました。クラウドブラウザーでのローカル file URL 表示も URL ポリシーで拒否されました。制約を回避せず、DOM 検証に留めています。

そのため、実ブラウザーの PC・スマホ画面、キーボード・スクロール表示、実 API と接続した保存・競合・通信失敗の通しテスト、サイト全体の lint / typecheck / build は未実施です。既存 API の再試行コード自体は変更していませんが、そのことは実接続テストの代わりにはなりません。

公開前に、通常の Work 実行環境で上記を確認し、ユーザーの公開承認を得てください。本変更は未公開のレビュー用です。
