# 管理票を開く通信の削減（未公開案）

## 既存改善との違い
公開基準 ce91687 は一覧の list-snapshot、一回10件の read-many、要求の重複抑止、ScriptLock 競合回避の直列キューを既に含む。これらは変更しない。PR15 のチェックリストは通信を追加していない。

現行の一覧から管理票を開く操作では list → read を直列実行する。本案は共有管理者が30秒以内の取得済み一覧から既知の案件を選んだ場合のみ、移動先一覧の再取得を省き、最新案件 read を必ず実行する。詳細・権限・version・保存結果は保持して使い回さない。

## 守る条件
- 初回、一覧表示、明示的な再読込、ディープリンク、新規作成、保存後は既存の最新取得。
- 対象外ID、30秒経過、時計の逆行は最新一覧に戻る。失敗時に古い詳細を表示しない。
- 認証ロック、purge、手動保存開始、現在の読取エラーで移動先一覧を消去。
- 画面に移動先候補が直前一覧であることを明記。候補も更新するには再読み込み。
- 世代番号、入力破棄確認、競合・結果不明時の同一キー再試行を維持。自動再試行は追加しない。
- 申請者画面、サーバー、承認・通知の処理は変更しない。

## 検証
`node .github/scripts/test_admin_navigation.mjs`：実render関数と直列ディスパッチのfixture。最新version/権限、対象外ID、期限切れ、申請者除外、認証・読取エラー、A→Bの遅延応答、purge、入力中の読込、ディープリンク、実transportの連打抑止・不明結果と同一キー再試行を確認。

適用される一覧→管理票は2 RPCから1 RPCに削減。1 RPCを500msと置く計算では1000→500ms。これはfixtureモデルであり実利用の測定値ではない。ログイン・初回一覧・保存自体の遅延を解消したとはいえない。

既存Python39件、申請者Nodeテスト、新規チェックリスト構文/CSPテストも通過。実認証後のブラウザー試験、実GASの処理時間計測、サイト全体lint/buildは本変更では未実施。先の環境では依存導入が137で終了し、実ブラウザーのローカルfixtureも実行環境制約で表示できなかった。
